## 形态

第三章定了"生成→裁决→修正"的骨架，还差两个选择：**图用什么形式表达**，**裁判用什么方式交付**。答案是 SVG 和 MCP，两者都有硬依据。

## 为什么是 SVG

**1. 认知科学的旧结论：图示使空间关系显式化。** Larkin & Simon《Why a Diagram is (Sometimes) Worth Ten Thousand Words》（Cognitive Science, 1987, A 级）：信息等价≠计算等价——图示把文本里"隐含"的关系变成"直接读出"，大幅减少搜索与工作记忆。Scaife & Rogers（IJHCS 1996, A 级）进一步给出"外部认知"框架：外部表征实现计算卸载。**让 AI 先画 SVG 再推理，本质是给它装一个外部工作记忆。**

**2. SVG 是"可断言的图"。** 位图只能看，SVG 是代码：元素有 id、坐标、尺寸，可以解析、可以算 bbox、可以断言"rect[1] 在 circle[1] 左边 8px 外"。同一份 SVG 既是给人看的图，又是给裁判用的结构化数据，还是给 RL 用的可验证奖励源——三位一体。

**3. LLM 生成 SVG 的几何正确性普遍差，校验是刚需。** SVGenius/SVGEditBench（ACM MM 2025, B 级）统计的高频错误：path 命令错、坐标幻觉、文本溢出容器、锚点错位、元素出画布。这恰好说明"生成器 + 裁判"的分工是对的。

## 为什么是 MCP

**1. 生态空白（2026-10 核实）。** 现有 SVG-MCP（validate/render/diff/lint 有、几何断言**无**、项目停更）、svgmaker-mcp（云端 API）、excalidraw/mermaid/blender 类 MCP 都不做"几何关系断言/可验证奖励"。最接近的 GeoSVG-RL（B 级）是训练框架不是工具产品。裁判这个位置，当时没人坐。

**2. 工具协议就是"接口质量"问题。** Frontiers of CS 2025（A 级）工具学习综述：工具描述/接口质量直接决定调用成功率；Interface Drift（B 级）量化到**描述修复可把成功率从 0.58 拉到 0.81**；措辞差异甚至能造成 10 倍调用率差。所以"写好工具描述"不是文案工作，是接口工程——这也是后文 skill-opt 优化的对象。

**3. MCP 的错误语义天然匹配"可自纠反馈"。** 协议定义了 `isError` + 可自纠消息的通道：裁判的失败提示（差多少、往哪移）可以原样递到 AI 面前，不需要中间翻译层。

## 工具清单的取舍原则

BFCL 稳健性（B 级）：语义相近的工具放一起就掉点；Brittlebench（B 级）：语义扰动平均 -21%。所以工具数克制（最终 9 个）、单一职责、命名可区分：

```
校验内核（自研，差异化）：get_geometry / assert_relations / suggest_assertions
                          / check_layout_contract / score_reward
现成库封装（不造轮子）：validate_svg / render_svg / diff_render / lint_svg
```

`suggest_assertions` 是唯一一个"不裁决"的工具：它从几何反推候选断言，只给候选、不下结论。放在这里是因为**契约本身也得有人写**——让 AI 先看到"我画的图能被哪些断言描述"，比让它凭空猜契约靠谱。

## 20 条约束，三种单位，不可混算

约束不是一个列表，是三个族。混着算就会出错：

| 族 | 条数 | 单位 | 为什么必须独立 |
| --- | --- | --- | --- |
| bbox 族（`left_of` `align_x` `contains` …） | 13 | px | 位置类关系的定义**就是** bbox 关系，换像素只会引入噪声 |
| 轨迹族（`on_path` `points_toward`） | 2 | px | 在真实采样折线上算。"在线上""朝哪边"用 bbox 根本无法表达 |
| 掩膜族（`mask_overlap` `mask_coverage` …） | 5 | ratio | 在**真实绘制像素**上算，修 bbox 的过近似 |

`deviation_px`（px）与 `deviation_ratio`（无量纲）被强制分组输出，跨单位不可排序、不可平均——2px 和 0.01 比大小是没有意义的。

**为什么非要有掩膜族**：bbox 是外接矩形，它忠实回答的是"外接框是否相交"，不是"图形是否真的接触"。五个定向构造的对照里，两种度量**结论全部相反**：

| 场景 | bbox 判定 | 掩膜判定 |
| --- | --- | --- |
| 斜线 vs 圆 | 相交（bbox 交 648px²） | 完全分离（重叠 0 像素） |
| 两圆对角排布 | 相交（bbox 交 841px²） | 分开（圆心距 100.4 > 100） |
| 三圆完全重合 | 等距完美（间距 0） | 退化成同一块（collapse 0.33） |
| `fill=none` 的矩形 | 在画布内、位置合法 | 一个像素都没画出来 |
| U 形 vs 实心方 | 尺寸完全相同 | 覆盖 62.5% vs 100% |

注意 bbox 那列**不是算错了**：它算的是自己定义的那个量。分歧来自"问错了问题"。反过来说掩膜也有硬边界——它是隔离渲染得到的，表达不了"被上层遮挡"，`filter`/混合模式会让它失真。

## 它到底能用在什么地方

能谈的场景必须限定在同一类：**已有或将有 SVG 文本，需要机器判定其布局是否符合一个可陈述的契约**。它不读像素图像、不做目标检测、不推断"图里有什么"。

**直接成立**（工具能力直接覆盖）：LLM 生成 SVG 后的自动验收；流程图连线是否真连上（用真实端点而非 bbox 角点）；"声明了却没画出来"的空壳元素；bbox 相交但像素没碰的假相交；标签溢出容器；图表对齐/等距；资产改版回归。

**有条件成立**：批量设计规范检查（取决于契约写得多全，写不全分数就失真）；Skill/Prompt 自动优化闭环（管道已通，真实优化轮仍缺 LLM 凭据，见第 7 章）。

**不适用**：照片/自然图像的空间理解（输入只有文本）；目标检测/语义分割（无检测器，元素身份来自 `id`）；视频时序推理（只有掩膜族支持 `at` 单帧，其余永远描述 t=0）；3D 遮挡（无 z 轴）；"证明模型具备空间推理能力"（N=30 自建，见第 5 章）。

一句话定位：**它是几何事实核查员，不是绘图 AI**——只判"哪里偏了多少、往哪改"，不负责生成。

## 一句话结论

SVG 让空间关系**可断言**，MCP 让裁判**随取随用**，工具描述质量决定 AI 用不用得起来。三者凑齐，第三章的范式才从论文变成手边的工具。
