## 形态

工具写完了不等于写好了——第 5 章实证里暴露的缺陷（语义歧义、评分归并错误）需要**优化循环**来修。但"改提示/改描述"最容易犯的错是：改了 20 处，好了 3 处坏了 4 处，还不知道哪处起了作用。skill-opt 的门控纪律就是治这个的。

## 循环四步（配硬工具，不靠自觉）

```
失败案例 → 5Why 追问（结构校验不通过不许升级）
   ↓ 根因假设
对策候选 → gate 查重（被否过的对策换个姿势重提直接拦截）
   ↓ 门控通过
≤4 处编辑（有界改进，保证可归因）
   ↓
独立复测（换场景，"和之前差不多"不算通过）
```

## 一次真实的走完整循环

**失败**：基线 0.8892 未达收敛线，26 例违例中 7 例集中在等距/连接线类。

**5Why（结构校验通过）**：Why1 违例分布 → Why2 为什么等距/连接线错最多 → Why3（制造）描述模板五要素里没有"计算口径" → Why4（检验）验收只测引擎不测"描述→行为" → Why5（体系）流程缺"描述-实现一致性"闸。
**根因**：工具描述缺「计算口径」必填项（equidistant=中心间距、connectors=端点必须画到目标边缘），生成方按直觉留空隙/按边缘间距绘制。

**对策与门控**：

- 对策 A：把容差默认值 2px 放宽到 5px，让基线"过线" → **拒绝**，写入拒绝缓存。理由：不修根因、掩盖偏差量，属于对指标动手而不是对问题动手。
- 对策 B：描述补"计算口径"句 + 模板加必填项 + 验收加一致性回归 → **采纳**，4 处编辑封顶。

**独立复测**：pytest 57/57 零回归（该轮口径；测试套件后续扩充到 119 项，仍全绿）；30 卡复测 1.0000；一致性回归测试固化"口径句不得再丢"。

## 可复用的三条经验

**1. 工具描述六要素**（缺一不可）：用途 / 参数单位与范围 / **计算口径（判定算法语义，必须与实现一致）** / 成功示例 / 失败示例与失败语义 / 选择器语法。第六要素"计算口径"就是这次教训换来的——描述写的是"怎么用"，但 AI 真正需要的是"裁判怎么判"。

**2. 消融要诚实标注做法，也要诚实标注阻塞。** 本次是**归因式消融**：按 26 例失败的逐例归因，统计"缺哪个描述要素会多错哪类"（口径→7 例、失败语义→26 例、容差语义→2 例）。这不等于"删除要素→第三方 LLM 重生成→计分"的全量消融。**没做的实验不许写成做过的结论。**

**3. 一次被推翻的归档。** 全量消融原先被记成"只缺 API 密钥"，看起来是个资源问题。2026-10-29 复核发现真实阻塞是**三层叠加**：

1. **env adapter 未实现**——`EnvAdapter.rollout()` 是空的，40 张卡根本接不上评分器；
2. **env 未注册**——`get_adapter()` 查的注册表里没有这个环境，即便有密钥也会直接 `Unknown environment`；
3. **缺 LLM 凭据**——配置文件里三处仍是占位符。

第 1、2 层当天补完：写了 adapter（40 张卡 → 评分器 → 逐卡落盘预测），用运行期注册把环境挂进注册表（**没有改 site-packages**），再用确定性重放策略（重放既有基线 SVG，不调模型）实跑通整条链——30 张空间卡重放得 **0.8892**，与既有 CSV 台账**逐位一致**，说明管道没有偷偷改变分数。退化对照（只含无关 `<rect>`）在 hard 上 0/30 满分，基线 4/30，证明打分器不是返回常数。

第 3 层依然缺，所以**真实优化轮仍未跑**，5 组种子的对比结论依然不存在。

这次教训比结论本身更有用：**把"没做"归档成"缺资源"之前，先验证资源是不是唯一阻塞。** 一句"等有密钥再跑"，把两层工程量藏了整整一天。

## 一句话结论

优化不是"改到看起来对"，而是：根因可证伪、对策过门控、改动可归因、复测换场景、消融标方法。投机对策（改容差过线）被拒绝缓存拦住的那一刻，这套纪律就回本了。
