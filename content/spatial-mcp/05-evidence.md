## 形态

前面四章是论证，这一章是数字。项目 `svg-spatial-mcp`（9 个工具的 MCP 服务器）落地后，用 30 张场景卡做了对照实验：

| 指标 | 基线（裸生成，单次出图） | 修正集（断言反馈一轮修正后） |
| --- | --- | --- |
| mean_total（6 维加权） | **0.8892** | **1.0000** |
| 完美案例（≥0.999） | 4/30 | 30/30 |
| 空间布局类（10 卡） | 0.9194 | 1.0000 |
| 组合泛化类（10 卡） | 0.8528 | 1.0000 |
| 图示类（10 卡） | 0.8954 | 1.0000 |

数字以 `results_baseline.csv` / `results_assisted.csv` 逐例台账为准（此表 2026-10-29 按 CSV 重算核对，早前正文里的 0.8889 与 0.8945 是笔误，已更正）。

**评测协议**：30 张场景卡（自然语言任务 + 期望几何契约 JSON），由 6 维契约评分器打分——渲染合法性 / 画布适配 / 锚点精度 / 文本入框 / 图连通 / 代码整洁。两臂生成方为同一 AI，唯一差异是**是否获得确定性裁判的反馈**。

## 基线失败分布（26 例失败，逐例归因）

| 失败类型 | 例数 | 典型偏差 | 裁判反馈 |
| --- | --- | --- | --- |
| 对齐类 | 7 | 中心 y 偏 8px | "垂直移动 8.0px 对齐 y=138.0" |
| 等距不均 | 4 | gaps=[90,120] | "间距调至 ~105.0px" |
| 连接线未接触 | 3 | 端点留空 10-20px | "端点距目标 > 6px，画到目标边缘" |
| 包含/文本溢出 | 5 | 文本溢出容器 28px | 给出容器与内容的 bbox 差值 |
| 方向错 | 4 | 三角画到了左边 | "右移至少 198px" |
| 出画布/尺寸不一 | 3 | 节点超出画布 | 给出超出量 |

**关键观察：26 个失败例全部被"元素-约束-偏差量"级提示一轮修正，没有一例需要猜测。** 这是第三章"反馈粒度决定收敛速度"的直接实证。

## 顺手抓到的四个引擎级教训

评测过程本身就是对裁判的打磨（详见[第 6 章](/spatial-mcp/06-skillopt-method/)）：

1. **契约断言必须折入总分。** 初版评分器里 `contains` 断言失败居然不影响总分——断言只做了记录没做归并，两个明显画错的案例拿了满分。修法：断言按类型折入对应维度取 min。
2. **容差内不该扣分。** 初版锚点评分是 `1 - err/tol`，误差 1.4px、容差 2px 的案例被扣掉 70% 的分。修法：容差内记满分，超容差线性衰减。
3. **满分的维度不该输出"失败"。** "未提供 connectors，按满分计"这种说明性文字混在 failures 里会污染统计。修法：说明进 warnings，failures 只放真失败。
4. **裁判遇到"元素少画了"必须扣分，不能崩。** 2026-10-29 发现的真实缺陷：`assert_relations` 的批量断言只捕获了"规格错误"，没捕获"选择器匹配不到元素"。于是被测 SVG 只要少画一个契约里点名的 `#circle`，整批评分不是判 fail，而是抛异常——**裁判把"你画错了"报成了"我算不了"**。这个缺陷一直藏着，是因为基线集的 30 张卡 id 齐全，谁也没测过缺元素的情况。
   修法与验证：把选择器未命中按"该条断言 fail + hint 标注、不中断其余断言"处理（与工具描述里早写明的失败语义对齐）；实测缺 `#circle` 的 SVG 由抛异常变为 `0.8333`，同一批里的 `inside_canvas` 仍判 pass；完整 SVG 仍为 `1.0000`；30 卡台账重算逐位不变。

## 但分数还有一层口径要知道

**一条软分数的地板不是 0，而是约 0.74。** 用一组只含无关 `<rect>` 的退化 SVG 跑同一批契约，实测 `mean_soft = 0.7389`（自建，2026-10-29 跑 `skillopt_env` 自检得出）——一个画错的东西仍拿七成四分。

原因在契约本身：30 张卡大多只给 `assertions`，没给 `expected_anchors` / `text_boxes` / `connectors`。而评分器的设计是"未指定的维度不惩罚"，于是 `anchor_precision` / `text_in_box` / `graph_connectivity` 走"无规格即满分"分支，6 维里有 4 维白送。

后果有两条，都得说清：

- `soft` 实际只在 **0.74–1.00** 这条窄带里区分，作为连续奖励（RL / 拒绝采样）信息量很低；
- 本章的 `0.8892` 是**契约相对分**，不是绝对质量分。它的正确读法是"相对这批契约的达标程度"，不能读成"图有 89% 正确"。

这个口径问题**尚未修**（两种改法：未指定维度按已指定维度归一，或给 0 而非 1；都会改动既有台账，需要先定口径再动）。**在改之前，本章只把 hard 判定（是否 ≥0.999 完美）当硬结论用。**

## 这个对比能说明什么、不能说明什么

**能说明**：裁判给出的偏差量足够硬——26 个失败例全部靠"元素-约束-偏差量"级提示完成修正，没有一例需要猜；修正后 30/30 全 pass，说明"偏差 → 修正 → 复核"这个闭环在机制上成立。

**不能说明**：这个提升幅度不是模型能力的提升。修正集的生成方拿到的就是裁判自己给出的 hint，按 hint 改坐标属于**照着答案改**——所以 `1.0000` 证明的是"裁判指的方向是对的、闭环能合上"，不能证明"模型自己能把这张图画对"。这属于自证循环，真正的能力测量必须换第三方模型盲测。

另外如实声明：出题人和答题人是同一个 AI，存在先验污染；数字的证据等级是**自建（N=30）**，不是 A/B/C 任何一级。
