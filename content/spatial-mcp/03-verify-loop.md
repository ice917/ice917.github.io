## 形态

第二章的 A 级证据其实指了路：起作用的不是"教模型会算"，而是**"可验证奖励"**。把裁判从模型手里拿走，交给一个确定性程序：

```
模型生成（画 SVG / 写程序 / 出方案）
   ↓
确定性验证器裁决（几何断言 / 形式证明器 / 单元测试）
   ↓ 返回"元素-约束-偏差量"级的失败信息
模型按偏差修正
   ↓ 循环直到全 pass
```

这不是工程技巧，是**Nature 三次背书过的范式**：

| 工作 | 做法 | 结果 | 等级 |
| --- | --- | --- | --- |
| FunSearch（Nature 625:468, 2023） | LLM 生成程序 + 自动评估器迭代过滤 | cap set 构造超越人类已知最优 | A |
| AlphaGeometry（Nature 625:476, 2024） | 神经 LM + 符号演绎引擎 | 奥赛几何 30 题解 25（此前 SOTA 10） | A |
| AlphaProof（Nature, 2025） | 形式化证明校验器当 RL 奖励 | IMO 历史题金牌水平 | A |

## 三条铁的设计原则

**1. 裁决权不给模型。** IEEE TSE 2024（A 级）系统实验证明 LLM 自我验证不可靠——它说"检查过了没问题"和"真没问题"是两件事。所以校验必须是确定性程序：算 bbox、算交集、算偏差，同一输入永远同一输出。

**2. 反馈粒度决定收敛速度。** ACL 2025（B 级）量化了这一点：执行**中间状态**的反馈显著优于事后整体判定（"Self-Generated Tests"会被测试偏差误导）。翻译到空间任务：返回 pass/fail 没用，返回"circle[1] 与 rect[1] 中心 y 相差 8.0px，请垂直移动 8.0px"才有用——这叫**元素-约束-偏差量**级反馈。

**3. 修正靠偏差不靠猜。** 有了偏差量，修正变成算术：往哪移、移多少，全部由裁判给出。猜测性修正（"大概往左一点"）是收敛慢的根源。

## 这个范式在空间任务上的形态

空间关系有一个绝佳性质：**可以用几何断言完全定义**。"左边"= a 的右边缘 ≤ b 的左边缘 + 容差；"包含"= a 的 bbox 完整包住 b；"等距"= 相邻中心间距相等……每一类关系都有确定性判定，天然适合做裁判。

于是架构定型：

- **生成端**：LLM 画图（SVG 代码）；
- **裁决端**：几何断言引擎（bbox 变换展平 + 关系判定）；
- **反馈端**：逐条断言的 deviation_px + 修正方向；
- **总评端**：多维契约评分 + 标量奖励（顺便是未来 RL 的奖励函数）。

## 一句话结论

与其花算力把模型"教到会算"，不如给它一个**永远算不错的裁判 + 精确到像素的反馈**。Nature 三篇验证了这条路能出顶级结果；剩下的问题是：用什么形式表达"图"，用什么协议交付"裁判"。
